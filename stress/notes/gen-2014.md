# gen-2014 notes

## old-hexblade-6
Intent: 2014 Variant Human + Warlock 6 Hexblade (XGE), Pact of the Blade written as `Options:`,
invocations, spells-known progression with a level-6 swap.

- DATA: `data/slots.json` has no separate "Variant Human" species entry — `Human|PHB` has
  `"ability": null` and `"versions": []`, i.e. the data does not even record base Human's
  usual +1-to-all bonus, let alone the Variant Human alternate rule (skill + feat + two +1s).
  Wrote `Species: Human` and added `ASI: +1 DEX, +1 CHA`, `Skills: Insight`, `Feat: War Caster`
  directly in the block — that's the only way to signal "this is the variant", since nothing
  else distinguishes it from base Human picking its one extra language.
- GAP: there is no key for "which optional/variant rule of a species/background is in play" —
  the paste can only show its effects (the picks), never name the toggle itself.
- DATA: The Hexblade is `The Hexblade|Warlock|PHB|XGE` in slots.json; wrote it by short name
  `Hexblade|XGE` per §3.2 (subclasses matchable by printed or short name). Tagged `|XGE`
  because it's a supplement subclass, not a core-book one, even though it's unambiguous
  without the tag under `Rules: 2014`.
- AMBIGUOUS (§5.1 `Options`): the 2014 Pact Boon ("Pact of the Blade") is not tagged with any
  dedicated key — it lives under the same `Options:` bucket as invocations, exactly as the
  brief and D27 intend, but nothing in the AST marks it as *the* boon vs. an invocation; a
  consumer must know from game data that `Pact of the Blade` belongs to the `PB` family.
- Spells-known progression: 2(L1)→3(L2)→4(L3)→5(L4)→6(L5)→7(L6). At L6 demonstrated the
  standard "swap one known spell on level-up" rule with `-Armor of Agathys, Fear, Vampiric
  Touch` (drop 1, add 2 — one normal new spell, one replacement) to land back on the correct
  total of 7.
- SMELL: `Background: Charlatan` ends up an empty block (all its skills/tools are fixed,
  nothing chosen) — just the header line with no lines under it, which is allowed but looks
  odd next to a populated Species block.

## old-hexblade-6.reduced
Flat variant: identifier + `Classes`, `Subclass`, `Options` only, no `Rules`, no blocks, no
levels. Dropping `Rules` here loses the 2014/2024 disambiguation the full build relies on
(SMELL) — the brief's "only Classes, Subclass, Options" cut it, but a real flat snapshot of a
2014 build probably wants `Rules: 2014` kept for the same reason `Species`/`Background` items
keep a source tag.

## old-battlemaster-10
Intent: Fighter 10 Battle Master (PHB), manoeuvres as `Options:` at L3/L7/L10 with a swap at
L10, Fighting Style as the (nominally) optional feature it mechanically is, Tasha's
"Martial Versatility".

- Maneuvers known: 3(L3: Precision Attack, Trip Attack, Riposte) → 5(L7: + Menacing Attack,
  Disarming Attack) → 7(L10: -Riposte, + Parry, Commander's Strike, Sweeping Attack — drop 1,
  add 3, net +2 to land on 7, with the swap folded into the level-up griant).
- DATA/AMBIGUOUS: `Fighting Style` has its own dedicated key (§5.1) even though 5etools files
  it under `optionalFeatures` family `FS:F` alongside every other optional feature. The format
  never asks you to route it through `Options:` — it's the one family with a bespoke key
  (per §5.1's own text: "2014 optional feature ... same key either way"). Wrote
  `Fighting Style: Dueling` at L1 accordingly; recording this because the brief specifically
  asked to note "fighting style as an optional feature" and the answer is that the spec
  deliberately special-cases it, so there's nothing to work around.
- GAP: Tasha's "Martial Versatility" (TCE optional class feature letting a Fighter retrain a
  fighting style, or trade a feat for an ASI and vice versa, at every ASI level) is **not
  present anywhere in `data/slots.json`** — not in `optionalFeatures`, not in `classes`
  `features`/`options` (those are empty for every class). Wanted to write something like
  `Feature: Martial Versatility [retrain Dueling → Defense]` but `Feature` details must follow
  a printed pick order the checker knows, and there is no such entry to check against. Settled
  for `Options: Martial Versatility|TCE` at L6 (it *is* an optional class feature, so `Options`
  is the right bucket per D27) with no detail bracket, since there's no known slot shape for
  its retrain pick. This only records that the feature was taken, not what it did on that use.

## old-battlemaster-10.reduced
Same build with every `Options:` line removed. That empties L7 and L10 entirely (they had no
other lines), so those level headers were dropped too rather than left as bodiless headers —
SMELL: stripping one key can silently delete whole level blocks, which a naive line-diff
"remove Options lines" tool would not do (it would leave two headers with nothing under them).

## old-tasha-ranger-7
Intent: Ranger 7 (PHB) with TCE's Favored Foe/Deft Explorer replacing Favored
Enemy/Natural Explorer, Fighting Style, spells-known progression.

- DATA: same gap as Martial Versatility — `Favored Foe` and `Deft Explorer` are TCE optional
  class features with zero hits anywhere in `data/slots.json` (checked `optionalFeatures`,
  `classes.*.features`, `classes.*.options` — all empty/absent). They are real 5etools content
  (TCE), just not in this snapshot's tables, so tagged them `|TCE` rather than `|HB` and wrote
  them via `Options:` at L1 (the level the base features they replace are normally granted).
- Spells known: 2(L2: Hunter's Mark, Cure Wounds) → 3(L3: + Longstrider) → 4(L5: + Pass without
  Trace) → 5(L7: + Lesser Restoration). No swap needed here, unlike the Warlock build.
- No `Subclass` omission issue: `Hunter|Ranger|PHB|PHB` resolves fine bare under `Rules: 2014`.

## old-subrace-cleric-5
Intent: 2014 subrace + Life Domain Cleric 5, fixed-skill background, cantrips-only (no
`Spells` line, since Cleric prepares from the whole list).

- DATA: `data/slots.json`'s `species` table has **no Hill Dwarf / Wood Elf entries at all** —
  only base `Dwarf|PHB` (`ability.fixed = {con: 2}`) and base `Elf|PHB` (`ability.fixed =
  {dex: 2}`), each with `versions: []`. There is no way to name "Hill Dwarf" or "Wood Elf" as
  a 5etools entity in this data, contrary to the brief's suggestion that `data/slots.json`
  would hold a name like `Species: Elf (Wood)|PHB` — it doesn't; 2014 subraces are simply
  absent from the table.
- Per the brief's own rule ("2014 species have fixed ability bonuses — no ASI line needed
  unless the species chooses"), a subrace's bonus is not a player choice, so I did **not**
  write an `ASI` line for the Hill Dwarf's extra +1 WIS — but that also means it is invisible:
  the paste can show `Species: Dwarf` (base) and nothing distinguishes "plain Dwarf" from
  "Hill Dwarf" at all, since the subrace name, its extra ability bonus, and its automatic
  feature (Dwarven Toughness) have no home in the format or the data. This is the sharpest
  GAP in the whole set: a real, common, non-homebrew build fact (subrace choice) that the
  2014-era paste cannot record even in principle, not because of a spec limitation but
  because the checker's data model was built subrace-blind.
- `Tools: Brewer's Supplies` is the one real Dwarf choice the data does support (`tools.choose`
  from smith's/brewer's/mason's).
- `Background: Acolyte` — skills (Insight, Religion) are fixed, not written; `languages.any:
  2` is a real choice, written as `Languages: Celestial, Infernal`.
- `Cantrips: Toll the Dead|XGE` at L4 — tagged because Toll the Dead is XGE-sourced, not PHB,
  unlike Guidance/Light/Sacred Flame.
- No `Spells` or `Prepared` line anywhere, per the brief: Cleric prepares from its whole list,
  so there is no "spells added to repertoire" fact to record.

## old-artificer-9
Intent: Artificer 9 (TCE) Battle Smith, infusions as `Options:` with count growth and a
replaced infusion, 2014-style starting equipment as items (no option letters).

- Infusions known: 4(L2) → 6(L6, via `-Boots of the Winding Path, Resistant Armor, Replicate
  Magic Item, Radiant Weapon` — drop 1, add 3, net +2 folds the swap into the level-up grant).
  `data/slots.json` has no `Artificer` infusion-count progression table either (same absence
  pattern as classes' `features`), so the 4→6 count is from memory of the TCE table, not
  verified against data — flagging as AMBIGUOUS since nothing in this repo's data could
  confirm or deny it.
- DATA: `Equipment` items for a mundane starting kit are patchy in `data/items` — no
  `Dungeoneer's Pack`, no `Thieves' Tools`, no `Component Pouch` entries exist in the table at
  all (checked all three directly), even though they're standard PHB gear. Built the
  equipment line only from names that do resolve (`Studded Leather Armor`, `Light Crossbow`,
  `Crossbow Bolts (20)`, `Smith's Tools`, `Dagger`) rather than write unresolvable names.
- `Classes: Artificer 9` and `Subclass: Battle Smith` both resolve bare under `Rules: 2014` —
  `Artificer|TCE` is tagged `edition: 2014` in the data (vs `Artificer|EFA` at `2024`), so the
  `Rules` default does the disambiguation exactly as documented even for a non-PHB class.
- Per brief: wrote `Equipment` at L1 as bare items, no option letter, since "letters exist only
  under 2024 rules; 2014 builds list items" (§5.1).

## Cross-cutting
- DATA (general): three of five builds needed a real, non-homebrew 5etools feature/subrace
  that simply is not present anywhere in `data/slots.json` — Tasha's optional class features
  (Martial Versatility, Favored Foe, Deft Explorer) and 2014 subraces (Hill Dwarf, Wood Elf).
  None of these are obscure; they're exactly the kind of build fact this stress pass was meant
  to exercise. Recorded as `|TCE` (real book, just missing from the table) rather than `|HB`
  (homebrew) wherever the name is genuine 5etools content — treating a data gap as if it were
  homebrew would be the wrong signal for the checker to eventually pick up.
